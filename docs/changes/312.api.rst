With ``conv_backend="hexagdly"``, ``kernel_size`` and the pooling size are now read as a square-kernel width, like for the square backend, instead of a number of hexagonal rings. The same configuration therefore describes comparable models on both grids: a ``kernel_size`` of 3 is the 7-cell hexagon and 1 is a plain 1x1, which also makes the hardcoded ``kernel_size=1`` projections of the ResNet true 1x1 convolutions. A hexagonal model built from a configuration now has smaller kernels than before, so it must be trained again; models saved with an earlier version still load unchanged. A hexagonal window is centred on a cell, so it has no even size: an even ``kernel_size`` or pooling size is rounded up to the next odd one (2 gives the 7-cell window of 3, not the identity of 1), and the hexagonal layers say so with a warning. Note that the default pooling size of 2 triggers it with ``conv_backend="hexagdly"``. Requires ``keras-hexagdly>=0.6.1`` and ``pytorch-hexagdly>=0.4.1``.
